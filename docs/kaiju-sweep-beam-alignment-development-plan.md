# Kaiju 가속 횡단 빔·입 방향 동기화 개발계획서

## 1. 목표와 범위

몬스터가 가속 횡단 빔을 발사할 때 **실제 입이 향하는 방향, 보이는 빔, 피해 판정의 중심선**이 같은 프레임에서 일치하도록 개선한다.

기본안인 **패턴 주도 방향 + 실제 목·머리 보정**을 구현했다. 현재 화면 횡단 방향과 느린/빠른 진행률을 유지한다. 단순히 빔을 `Mouth.forward`로 교체하면 애니메이션의 각도·속도가 공격 범위와 회피 시간을 결정하게 되므로 그 방식은 채택하지 않았다. 아래 설계·단계는 개발 근거로 보존하고, 실제 적용 범위와 검증 결과는 **§12**를 기준으로 확인한다. 자동 검증이 모든 기기에서의 최종 아트 승인을 뜻하지는 않는다.

v0.1.0 작성 단계에서는 문서만 변경했다. v0.2.0 구현에서는 게임 코드와 BattleArena 입 소켓 회전을 수정했으며 원본 FBX, 애니메이션 클립, 전투 수치는 보존했다.

| 구분 | 범위 |
| --- | --- |
| 직접 수정 대상 | `KaijuHeavyThreats`의 `AcceleratingSweepBeam` 준비·발사·회복 과정, 입 소켓 보정, 목·머리 조준, 방향 검증 |
| 보존할 동작 | 화면 좌우 횡단 방향 선택, 경고 시간, 느린/빠른 구간, 폭·길이·피해·쿨다운, 패턴 선택 순서 |
| 회귀 확인 대상 | 추적 잔류 빔, 파편 일제사격/산탄, 점프 턴, 사망, 기존 `Attack1/Attack2` 호환 호출 |
| 제외 | 피해 재밸런싱, 새 몬스터·VFX 도입, 원본 FBX 수정, 전체 Animator 재설계, 레거시 패턴 재활성화 |

## 2. 문서 기준과 확인 수준

게임 시스템 기준은 [게임 시스템 중심 문서](cur_state/titan-destroyer-game-system-master.md)다. 실제 파일은 `docs/cur_state/`에 있다. 계획 당시에는 `AGENTS.md`의 경로가 달랐으나, 2026-08-29 전체 변경사항 공유 전 점검에서 지침을 실제 경로로 수정했다. 중심 문서 자체는 이동·복제하지 않았다.

중심 문서의 기존 게임 전반 검증일은 2026-08-05이며, 2026-08-26 Kaiju 애니메이션 통합 이후의 모든 동작을 검증한 문서는 아니다. [Kaiju 애니메이션 통합 계획서](kaiju-animation-integration-plan.md)는 해당 통합의 구현 이력으로만 참고한다. 충돌하는 동작을 과거 기획에 맞춰 복원하지 않는다.

- **구현됨:** 아래 소스와 씬에 현재 연결된 경로를 정적으로 확인한 것. 이번에 실행 테스트를 통과했다는 뜻은 아니다.
- **불일치:** 방향 소비 경로 또는 문서와 코드가 다름을 확인한 것.
- **프로토타입/디버그:** 개발용 재현·검증 도구. 정상 전투 설정과 분리한다.
- **계획:** 본 문서의 수정안·작업 단계·합격 기준. 현재 미구현이다.
- **레거시/비활성:** 기존 `LaserSweep` 등 현재 활성 세트 밖의 경로. 이번 작업에서 켜지 않는다.

### 추가로 실측해야 하는 사항

`KaijuMouthSocket`은 Head 아래에 있고 저장된 로컬 회전은 identity다. 이것만으로 축이 잘못됐다고 확정할 수는 없다. 리그 본의 +Z가 실제 입 정면이라는 보장도 없으므로, 메시의 입 중앙과 출사 방향을 보며 축을 보정해야 한다.

`leftToRight`는 현재 코드에서 **화면 기준**이다. 클립 이름의 좌우가 캐릭터 기준인지 화면 기준인지는 실측이 필요하다. 이름만 보고 클립 두 개를 맞바꾸지 않는다.

현재 빔은 처음 0.3초에 경로의 20%만 이동하고 다음 0.2초에 나머지를 이동한다. 반면 애니메이션은 활성 클립 구간의 전체 길이를 일정 배속으로 맞춘다. 따라서 시작/종료 이벤트를 맞추는 것만으로 중간 프레임의 방향까지 동기화되지는 않는다.

v0.1.0 검토 당시에는 Unity MCP 연결 세션을 확보하지 못했다. 이후 v0.2.0에서 Coplay로 실제 에디터에 연결해 소켓 축·클립 좌우·프레임 오차를 측정했다(§12).

## 4. 보존할 현재 수치와 경로

아래는 기본 씬과 코드로 확인한 값이다. 디버그 오버라이드는 재현 시 따로 기록한다.

| 항목 | 현재값 / 보존 기준 |
| --- | --- |
| 활성 조건 | 모든 보스 체력 구간, 현재 패턴 순서 유지 |
| 횡단 방향 | 매 공격 무작위 화면 좌→우 또는 우→좌 |
| 횡단 범위 | 우선 화면 경로 사용. `spreadAngle=92°`는 폴백값이며 고정 실제 각도로 강제하지 않음 |
| 경고 | 0.8초 |
| 느린 구간 | 0.3초 동안 진행률 `0 → 0.2` |
| 빠른 구간 | 0.2초 동안 `0.2 → 1`, 기존 `1 - (1 - t)^3` 보간 유지 |
| 활성 시간 | 0.5초, 프레임 양자화 허용 |
| 기본 폭 | `0.78 × 2.5 = 1.95` (계산값) |
| 빠른 구간 폭 | 기본 폭의 1.08~1.18배, 최종 2.301 (계산값) |
| 빔 길이 | `28 × 2.5 = 70` (계산값) |
| 피해 | 일반 피해 `15 × 1.2 = 18`, 기존 플레이어 피격 무적 적용 |
| 패턴 후 대기 | 기존 기본 공격 간격 × 1.2 |
| 애니메이션 이벤트 | 30fps 기준 시작 20 / 종료 68 / 회복 79프레임 |

화면 경로를 매 프레임 다시 계산하거나 빔을 임의로 수평면에 투영하지 않는다. 플레이어 고도와 카메라 기울기로 생기는 수직 성분까지 현재 방향에 포함되기 때문이다. 실제 화면 피복 범위는 움직이는 입 원점의 영향을 받으므로 A단계에서 기준 영상을 남겨 비교한다.

## 5. 설계안

### 5.1 방향과 자세의 소유권

| 방식 | 장점 | 위험 / 결정 |
| --- | --- | --- |
| 애니메이션 주도: 입 방향으로 빔 발사 | 입과 빔 연결이 직접적이고 구현이 작음 | 화면 횡단 범위·가속·회피 타이밍이 클립에 종속됨. 별도 게임플레이 변경을 승인할 경우의 대안 |
| 패턴 주도: 빔 방향에 실제 목·머리 자세를 맞춤 | 현재 공격 범위·속도 규칙을 유지할 수 있음 | 추가 자세 보정과 리그 한계 검증 필요. 본 계획의 기본안 |

`BossBulletPatternController`가 경로·진행률·피해 수명을 소유한다. `KaijuBossAnimationDriver`는 기존 클립을 기본 포즈로 재생하면서, 횡단 빔에 한정해 실제 목·머리를 목표 방향으로 보정한다. 보정 후의 입 위치와 목표 방향을 한 프레임 샘플로 묶어 VFX와 판정이 함께 소비한다.

보정 결과는 보정된 입 축과 목표 방향이 맞는지 검사한다. **소켓만 회전시켜 수치상 방향을 일치시키고 메시의 머리는 그대로 두는 방식은 사용하지 않는다.**

### 5.2 소켓과 리그 보정

1. 기존 FBX와 독립 `.anim` 파일을 보존한다. 격리 복제본에서 BasicIdle, 빔 시작·중간·종료 포즈를 확인한다.
2. 실제 입의 출구 중앙에 기존 소켓이 있는지 확인한다. 필요한 경우 BattleArena의 해당 소켓에만 위치·회전 오버라이드를 적용한다.
3. 소켓의 +Z가 입 밖을 향하도록 보정한다. 상·하악의 움직임 때문에 Head 자식만으로 부족하면 Head Upper/Jaw Under의 관계를 측정하고 최소한의 보조 앵커를 검토한다.
4. 기존 Neck_01/Neck_02/Head 중 필요한 본에만 yaw/pitch 보정을 분배한다. 새 리깅 패키지 설치나 Humanoid 전용 IK를 전제하지 않는다.
5. 각 프레임의 Animator 원본 포즈에서 보정량을 계산한다. 전 프레임의 보정에 다시 더해 누적 회전이 생기지 않도록 한다.
6. 목 꺾임·발 미끄러짐·입 위치 이동을 함께 확인한다. 현재 궤도가 허용할 수 없는 자세를 요구하면 제한각으로 몰래 잘라내지 않고 아래 결정 항목으로 돌린다.

입 소켓 위치를 바꾸면 다른 입 발사 패턴의 발사점도 바뀐다. 이동은 최소화하고, 위치 변경이 불가피하면 추적 잔류 빔과 파편 일제사격의 발사점 회귀를 필수로 수행한다.

### 5.3 한 프레임의 처리 순서

계획한 순서는 다음과 같다.

```text
패턴 시간·진행률로 목표 방향 계산
  → Animator의 현재 포즈 평가
  → 실제 목·머리 방향 보정
  → 보정 후 입 위치와 방향 검증
  → 공통 프레임 샘플로 빔 표시 + 피해 판정
```

- 프레임 샘플은 `attackId`, `origin`, 정규화된 `direction`, `width`, `length`, `damageActive`를 담는 소규모 내부 값으로 충분하다. 별도 범용 프레임워크를 만들지 않는다.
- 코루틴은 공격 수명/이벤트 대기를 관리하되 빔 표시와 피해를 각각 다른 갱신 시점에서 실행하지 않는다.
- 자세 보정과 입 좌표 읽기는 Animator 평가 뒤에 실행한다. `BattleController.LateUpdate`와 드라이버의 점프 턴 갱신 순서를 확인하고 명시적으로 순서를 정한다.
- 최종 입 위치는 목·머리 보정 뒤에 읽는다. 보정 전 좌표를 사용하면 빔 시작점이 다시 한 프레임 뒤처질 수 있다.
- 활성 빔은 동일 샘플로 프레임당 한 번만 일반 피해를 검사한다. 기존 코루틴 판정과 새 갱신 판정이 중복되지 않게 한다.

### 5.4 준비·발사·회복 동기화

- 준비 0.8초 동안 몸의 준비 동작을 유지하며 입이 시작 방향에 도달하도록 보정 가중치를 올린다. 방향 경고는 기존 시작 방향과 무피해 정책을 유지한다. 준비 초반의 예고선은 실제 발사 빔과 구분한다.
- `OnBeamStart`가 해당 공격 번호를 해제하고 경고 시간이 충족된 뒤 발사를 시작한다. 누락된 이벤트를 임의 시간 대기로 대체하지 않는다.
- 발사 시작점을 기준으로 하나의 활성 시간과 동일한 느린/빠른 진행률을 계산한다. 원본 포즈의 평균 배속만으로 방향 일치를 가정하지 않는다.
- 활성 중에는 입 보정이 목표 방향에 도달해야 한다. 보간 지연을 숨기기 위해 빔과 판정만 서로 다른 방향으로 보내지 않는다.
- 종료 프레임을 표시·판정한 뒤 빔을 정리하고 회복 단계에서 자세 보정을 해제한다. `OnBeamEnd/OnBeamRecovered`와 실제 빔 수명이 한 프레임 이상 어긋나지 않는지 검증한다.
- 매 프레임 `Animator.Play`로 시간을 강제 점프시키는 방식은 기본안에서 제외한다. 이벤트 중복·누락과 다른 공격 상태의 영향을 늘리기 때문이다.

### 5.5 중단·오류와 호환 경로

- 보스 사망, 전투 종료, 패턴 취소, 컴포넌트 비활성화/파괴 시 공격 샘플·빔·경고·자세 보정 소유권을 함께 해제한다. 늦게 온 이전 공격 이벤트는 새 공격을 활성화할 수 없다.
- 사망 포즈에는 살아 있을 때의 본 회전을 다시 덮어쓰지 않는다.
- 현재 `SetCinematicPaused(true)`는 패턴을 **취소**한다. 재개 시 취소된 빔을 되살리는 새 정책을 추가하지 않는다. 별도의 시간 정지에서는 시간 경과와 피해 누적이 진행되지 않아야 한다.
- 새 드라이버가 없는 구형 씬은 기존 폴백 경로를 유지한다. 드라이버가 있는데 필요한 소켓/본이 빠진 경우는 구형 씬과 구분하고, 횡단 빔을 안전하게 취소한 뒤 진단을 남기는 것을 기본안으로 한다.
- `TrackingResidualBeam`, `LaserSweep`, 호환 `Attack2`에 새 조준 보정을 무조건 적용하지 않는다. 횡단 빔 세션에만 한정해 회귀 범위를 줄인다.

## 7. 검증 계획과 완료 기준

수치 기준은 아래의 **계획상 초기 합격 기준**이며 아직 측정 결과가 아니다. 눈에 보이는 입 방향은 소켓 축 검사와 별도로 확인한다.

| 검사 | 계획상 합격 기준 |
| --- | --- |
| 입과 빔 각도 | 실제 입에 보정된 축과 빔 중심선의 활성 프레임 최대 오차 ≤ 2°. 소켓만 회전시킨 결과로 판정하지 않음 |
| 시작점 | 표시 빔의 근단과 최종 입 소켓 위치의 거리 ≤ 0.02 월드 단위. 입 내부 이격·옆면 관통은 영상에서도 없어야 함 |
| VFX/판정 일치 | 같은 프레임 샘플 사용. origin/direction/length 비교 오차 ≤ `1e-4`. 폭과 피격 반경은 기존 방식 유지 |
| 진행률 | 느린 구간 시작/끝 `0/0.2`, 빠른 구간 끝 `1`; 경계 연속, 양방향 단조 횡단, NaN/0벡터 없음 |
| 타이밍 | 기본 경고 0.8초·느린 0.3초·빠른 0.2초, 30/60/120fps에서 각 경계 오차 한 프레임 이내. 0으로 설정한 디버그 시간의 기존 최소 0.05초 처리도 유지 |
| 방향/피복 범위 | 같은 카메라·플레이어·시작 자세에서 기존 목표 벡터와 일치. 플레이어 깊이 평면과의 교차점으로 화면 범위를 비교하고 새 누락 영역이 없어야 함 |
| 피해 | 빔 중심선 접촉 시 원시 일반 피해 18, 기존 1초 피격 무적 및 일제사격 무적 유지. 새 중복 판정 없음 |
| 종료/재진입 | 취소·사망·비활성화 후 활성 빔/경고/조준 세션 0, 이후 다른 공격에 보정 잔여값 없음 |

재현 조건은 양방향 각각에 대해 플레이어 중앙·좌우 끝·상하 끝·대표 모서리, 실제 전투의 보스 회전과 추가 ±45°/±90° 조건, 화면비 16:9·19.5:9·4:3을 포함한다. 자동 검사로 조합을 넓히고, Game View와 입 근접 캡처는 대표 실패/성공 조건을 선택한다. 리그가 도달할 수 없는 조건은 통과로 처리하지 않고 §8의 결정 항목으로 남긴다.

추가 회귀 범위:

- 기존 Kaiju 포즈/이벤트 검사 전체, 연속 양방향 빔, 빔 직후 Firing/Tail/JumpTurn 전환.
- 준비/활성/회복 각각의 사망·취소·시네마틱 중단, 낮은 프레임률에서 이벤트 중복/누락.
- 추적 잔류 빔의 3피해/0.2초 경로, 일제사격 무적·피격 후 락온 취소 정책.
- 기본 활성 패턴 순환 및 최근 머지한 플레이어 정면 살보·환경 조명 회귀 테스트.
- 소켓/본 누락, 드라이버 없는 폴백, 카메라 부재의 각도 폴백, 씬 재진입.

검증 산출물은 실행한 테스트 이름·결과, Unity/커밋/씬 기준점, 각도·원점 최대 오차, 양방향 발사 전·중·후 화면, 기준 영상과의 화면 피복 비교, Console/Editor 로그다. 기존 테스트의 과거 성공 기록을 이번 수정의 성공 기록으로 재사용하지 않는다.

## 9. 변경 보호와 적용 순서

현재 사용자 변경인 `.gitignore`, `Earth4kMaterial.mat`, `.codex/`, `AGENTS.md`, `docs/README.md`를 보존한다. 구현을 시작할 때 작업 트리를 다시 확인하고, 미저장 씬은 자동 저장하거나 덮어쓰지 않는다.

코드 구현 완료 시 중심 문서 §7.3·§10·§11과 검증 메모/변경 이력, 이 계획서의 상태를 같은 작업에서 갱신한다. 부분 검증이면 `last_verified`가 게임 전체 검증을 의미하지 않도록 범위를 명시한다.

### 적용한 구현

- **구현됨:** BattleArena `KaijuMouthSocket`의 로컬 회전만 보정해 +Z를 실제 입 출사축으로 정렬했다. 기존 로컬 위치 `(-0.24138662, 1.1754575, -0.0063846977)`와 스케일은 보존했다. 양방향 클립을 샘플링한 실제 베이크 메시와 입 근접 캡처로 축을 확인했다. 씬 diff는 이 소켓의 회전 한 줄뿐이다.
- **구현됨:** `SelectSweepClipLeftToRight`가 시작/끝 방향의 Y축 부호 각도로 클립을 선택한다. 현재 정면 카메라에서 화면 좌→우는 `BeamRightToL`, 화면 우→좌는 `BeamLeftToR`에 대응한다. 기존 각도 폴백과 카메라 방향 회전도 같은 함수로 처리한다.

- **구현됨:** 드라이버 `Update`(실행 순서 -100)에서 직전 보정을 복구하고, Animator 평가 및 `BattleController.LateUpdate`(200) 이후 패턴 `LateUpdate`(300)에서 현재 포즈를 보정한다. 최종 입 위치를 읽어 `SweepFrame` 하나로 VFX와 일반 피해 판정을 실행한다. `Time.frameCount`로 같은 프레임의 중복 소비를 막고 시간 정지 중에는 피해를 시도하지 않는다.
- **구현됨:** 준비 중 보정 가중치를 올리고 활성 중에는 완전히 정렬한다. 정상 종료 뒤 최대 0.25초에 걸쳐 보정을 해제한다. 새 공격·취소·비활성화·사망은 즉시 해제하며 이전 포즈를 Death 애니메이션에 덮어쓰지 않는다. 드라이버가 있는데 소켓/본이 없으면 공격을 취소한다.
- **구현됨:** 준비 경계의 부동소수점 잔차와 중첩 코루틴 대기를 정리하고, 빔 시작 시 `Animator.Update(0f)`를 한 번 호출해 0초 포즈를 확정한다. 프레임마다 클립 시간을 점프시키지 않는다. `OnBeamStart`의 발사 승인과 누락 이벤트 취소 정책은 유지한다.

### 재실행과 검증 한계

`Tools > TitanDestroyer > Kaiju Combat`에 4번(보정 없는 샘플 캡처), 5번(보정 적용 샘플 캡처), 6번(실제 전투 조합 검사), 7번(발사 중 사망 검사)을 추가했다. 6번은 Play Mode에서 플레이어 위치·카메라 화면비·프레임 간격을 임시 제어한 뒤 복구한다. **7번은 테스트용 전투를 승리 상태로 종료하므로 새 Play 세션에서 실행한다.** 파일은 임시 폴더에 생성되고 경로가 로그에 표시된다.

모바일 실기기 빌드, 모든 고도·루트 회전 조합의 최종 아트 승인, 레거시 `LaserSweep` 재활성화는 수행하지 않았다. 루트 ±90° 검사는 리그 수학·복구 검사이며 해당 모든 자세의 아트 승인으로 해석하지 않는다. `TrackingResidualBeam`의 피해 공식은 변경하지 않았고 연속 피해 틱의 기존 회귀 테스트는 통과했으나, 이번 시각 정렬 수정은 가속 횡단 빔에만 적용된다.
