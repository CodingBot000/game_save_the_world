> **현재 구현에 맞춘 계획 문서**<br>

- 최종 정적 검증일: 2026-09-10

- 현재 전투 씬: `Assets/Scenes/BattleArena.unity/BattleArena.unity`

- 미실행: Unity PlayMode, EditMode Test Runner, 실제 기기/릴리스 빌드

## 수치 단위 규칙

- 이동·투사체·추적 속도는 **Unity 월드 단위/초**, 가속도는 **월드 단위/초²**다.
- 거리·폭·반경은 **Unity 월드 단위**, 시간은 `초`, 각도는 `도(°)`다.
- 피해는 게임 내부 **피해량**, HP/Hull/Armor는 해당 체력 포인트, DPS는 **피해/초**다.
- 배율·스케일·비율은 단위 없는 배수이며 기준값의 몇 배인지를 함께 적는다.
- viewport는 좌하단 `(0,0)`부터 우상단 `(1,1)`까지의 정규화 화면 좌표다.

## 1. 현재 전투 설계 기준

- 화면 기준 2D 평면에서 헬기를 이동해 단일 보스를 격파한다.
- 플레이어의 실제 공격은 자동 기관총과 1~5단계 락온 미사일뿐이다.
- 보스는 작은 탄막보다 파편·대형 투사체·횡단 빔·추적 빔을 사용한다.
- Armor는 실수를 흡수하지만 파손 후 Hull 피해가 1.25배가 된다.
- 보스 패턴은 라운드로빈이며 HP가 낮아질수록 패턴 사이 대기가 짧아지고 HP 65% 이하에서 추적 빔이 추가된다.
- 스테이지와 난이도 선택은 존재하지만 현재 전투 밸런스를 바꾸지 않는다.

## 3. 전투 진행 기준선

```text
t=0        플레이어/보스 초기화, 자동 기관총 발사 시작
t=2        기관총 휴지 시작
t=4        기관총 두 번째 발사 구간 + 보스 첫 패턴 시작
HP≤66.67%  Angry 대사 HUD
HP≤65%     Tracking Residual Beam 선택 가능
HP≤33.33%  Normal 대사 HUD
Boss HP=0  승리, R 재시작
Hull=0     패배, Retry/Quit
```

첫 보스 공격 4초와 기관총 4초 주기가 같은 시점에 겹친다. 이후 보스 패턴은 각 패턴의 실행 시간과 아래 쿨다운이 모두 지난 뒤 시작한다.

```text
CurrentAttackInterval = Lerp(0.9, 1.8, BossHealthRatio)
NextPatternDelay = CurrentAttackInterval × PatternCooldownMultiplier
```

| 보스 HP 비율 | 패턴 종료 후 기본 간격 |
| ---: | ---: |
| 100% | 1.8초 |
| 65% | 1.485초 |
| 50% | 1.35초 |
| 33% | 약 1.2초 |
| 0% | 0.9초 |

공통 규칙:

- 40발 고정 풀, 최대 요청 30발.

- 1~4락 발사 동안 약 0.6초 무적.

5락 장착 Sidewinder 2발은 0 피해의 연출용이다. 30발 전투 미사일과 총 기본 피해 100 피해는 별도로 유지한다.

## 5. 보스 패턴 잠금값

### 현재 씬의 라운드로빈

| 순서 | 패턴 | HP 조건 | 패턴 종료 후 쿨다운 배율 |
| ---: | --- | --- | ---: |
| 1번째 | Debris Fragment Scatter | 0~100% | 기본 공격 간격의 0.9배 |
| 2번째 | Debris Salvo | 0~100% | 기본 공격 간격의 1.05배 |
| 3번째 | Accelerating Sweep Beam | 0~100% | 기본 공격 간격의 1.2배 |
| 4번째 | Tracking Residual Beam | 0~65% | 기본 공격 간격의 1.35배 |

HP 65% 초과에서는 4번을 건너뛰고 1번으로 돌아간다. HP 65% 이하가 되면 다음 라운드로빈 탐색부터 4번이 선택 가능해진다.

### Debris Fragment Scatter

**형태 묘사:** 꼬리 충돌 지점 하나에서 작은 파편 7~10개가 부채꼴 소나기처럼 직선으로 퍼진다. 파편은 초당 260~720도로 제각각 회전하며 0.32초짜리 노랑·주황·빨강 궤적을 남긴다. 3~4개는 플레이어 근처 한 군집에 몰리고 나머지는 넓게 흩어져, 중심 회피와 주변 탄 확인을 동시에 요구한다.

| 항목 | 현재값/규칙 |
| --- | --- |
| 수량 | 사전 생성된 10개 배치 중 7~10개 |
| 간격 | 0.025초 |
| 피해/이동 속도 | 5.25 피해/개 / 6 월드 단위/초 |
| 스케일 | 원본 크기 0.45배 × 전역 2.5배 = 최종 1.125배 |
| 조준 | 3~4개 군집 + 넓은 산포 |
| 현재 준비 | Tail 애니메이션 48/30초 릴리즈 큐 = 1.6초 |
| 흔들림 | 릴리즈 시 0.1초, 카메라 로컬 위치 진폭 0.24 월드 단위 |

중요: `debrisFragmentStompCount=2`, `debrisFragmentStompDuration=0.2`는 AnimationDriver가 없을 때의 폴백이다. 현재 BattleArena에서는 Tail 애니메이션 경로가 실행된다. 씬의 `telegraphDuration=0.25`도 현재 실제 대기 시간을 정하지 않는다.

### Debris Salvo

**형태 묘사:** 보스 입에서 대형 투사체 2~4발을 한 발씩 던지는 연속 직사 공격이다. 첫 목표까지 얇은 주황색 조준선이 0.3초 나타나며, 투사체는 멀리서 작게 보이다가 접근하면서 커지고 초기 속도 6 월드 단위/초에서 가속한다. 패턴상 대형 파편 역할이지만 현재 `BossProjectile.prefab`은 주황색 재질의 Sphere 메시이므로 화면에서는 큰 주황색 구체탄으로 보인다. 첫 발 이후에도 각 발이 플레이어 주변을 새로 겨냥하므로 계속 이동하게 만든다.

| 항목 | 현재값/규칙 |
| --- | --- |
| 수량 | HP 손실 <1/3: 2발, ≥1/3: 3발, ≥2/3: 4발 |
| 첫 경고/발사 간격 | 0.3초 / 0.2초 |
| 피해 | 23.25 피해/발 |
| 현재 외형 | 주황색 Sphere 메시 `BossProjectile` |
| 속도 | 기준 12 월드 단위/초, 초기 6 월드 단위/초에서 목표 도달 1초 기준 가속 |
| 스케일 | 원본 크기 2.8배 × 전역 2.5배 = 최종 7.0배 |
| 접근 크기 | 최종 생성 크기의 0.25배 → 1.19배 |

### Accelerating Sweep Beam

**형태 묘사:** 보스 입을 회전축으로 삼은 긴 붉은 막대형 레이저가 화면 왼쪽 끝에서 오른쪽 끝 또는 그 반대로 수평 횡단한다. 얇은 경고 상태 0.8초 후, 전체 경로의 첫 20%를 0.3초 동안 천천히 움직이고 나머지 80%를 0.2초에 급가속해 쓸어버린다. 화면상으로는 와이퍼가 한 번 빠르게 지나가는 형태다.

| 항목 | 현재값/규칙 |
| --- | --- |
| 방향 | 좌/우 무작위 |
| 경고 | 0.8초 |
| 횡단 | 첫 20% 0.3초 + 나머지 80% 0.2초 |
| 피해 | 18 피해/피격 |
| 폭/길이 | 폭 1.95 / 길이 70 월드 단위, 빠른 구간 폭 최대 1.18배 |
| 경로 | 화면 좌우 정규화 viewport 기반. 92도는 실패 시 폴백 |

빔은 활성 0.5초 동안 매 프레임 일반 피해를 시도하지만 일반 피격 무적 1초가 적용되어 통상 한 번의 18 피해가 들어간다.

### Tracking Residual Beam

**형태 묘사:** 입에서 주황색 충전 구체가 0.5초 맥동한 뒤 플레이어를 향한 붉은 연결형 빔이 켜진다. 빔 끝점이 플레이어를 따라 움직여 보스 입을 중심으로 방향을 계속 틀며 4초간 유지된다. 현재는 지나간 자리에 잔류하는 장판형 공격이 아니라 접촉하는 동안 0.2초마다 피해를 주는 지속 추적 레이저다.

| 항목 | 현재값/규칙 |
| --- | --- |
| 조건 | Boss HP ≤65% |
| 준비/지속 | 0.5초 / 4초 |
| 추적 | 플레이어 기준 최대 속도의 0.4배, 현재 보통 4 월드 단위/초 |
| 피해 | 0.2초마다 3 피해/틱 = 15 피해/초 |
| 최대 원시 피해 | 4초 전부 접촉 시 60 피해 |
| 폭/길이 | 폭 1.55 / 길이 70 월드 단위 |

현재 사용하지 않는 직렬화 필드:

- `damageMultiplier=0.95배`
- `telegraphDuration=0.7초`
- `trackingTurnRate=28°/s`로 직렬화되어 있으나 현재 미사용
- `beamWarmupTrackingSpeedMultiplier=0.5배`

## 6. 비활성 공격과 잔존 데이터

| 항목 | 현재 판정 |
| --- | --- |
| Pressure Sniper | 현재 BattleArena의 4패턴 목록에 없음. 실행 코드는 남음 |
| Legacy Bullet Hell 5종 | 별도 세트로 남아 있으나 현재 비활성 |
| 단발 미사일 쿨다운 2.6초 / 150 피해/발 | `PlayerRuntimeState` 등에 잔존하나 락온 피해 계산에는 미사용 |
| Special 필살기 | 공격 컨트롤러/버튼 연결 없음. 일부 오버레이 에셋만 잔존 |
| 확률 크리티컬/클릭 조준 | 현재 피해 경로에서 미사용 |
| Air Pressure 회전/밀치기 | 대응 코드가 있으나 현재 4패턴이 호출하지 않음 |

코드의 `EnsureDefaultPatterns()`가 빈/구형 Kaiju 목록을 재생성할 때는 Pressure Sniper를 포함한 5패턴을 만든다. 현재 씬의 명시적 4패턴은 보존되지만, 씬 목록이 초기화되면 Pressure Sniper가 의도치 않게 다시 활성화될 수 있다.

## 8. 다음 설계·구현 우선순위

### P0 — 문서와 기본 데이터의 재발 방지

1. 공식 보스 패턴 수를 4종 또는 5종으로 확정한다.
2. 4종이 공식이면 코드 폴백 목록에서도 Pressure Sniper를 제거하고 회귀 테스트를 추가한다.
3. 파편 산탄의 `telegraphDuration`과 스톰프 폴백 필드가 실제 Tail 경로를 오해하게 하므로 이름·주석·디버그 패널 표시를 정리한다.

### P1 — 플레이 가능한 완성 흐름

1. 승리 오버레이에 Retry/Main Menu/Next Stage 정책을 확정한다.
2. 모바일 이동 입력과 승리 후 재시작 버튼을 구현한다.
3. 방송 HUD의 실제 트리거를 정한다. 후보는 첫 보스 패턴 시작과 실제 5락 완료다.
4. 지역/난이도 선택이 BattleArena에 미치는 값을 명시하고 연결한다.

### P1 — 전투 성장과 약점

1. 약점 개방 조건을 HP 구간, 특정 패턴 후, 부위 파괴 중 하나로 결정한다.
2. 남아 있는 `MissileDamage +10/레벨`을 제거하거나 락온 고정 피해표와 결합하는 공식을 정한다.
3. 정식 빌드에서 저장된 성장 스탯을 적용할 소유 컴포넌트를 확정한다.

### P2 — 튜닝 데이터 정리

1. 추적 빔의 미사용 필드 4개를 삭제하거나 공식에 연결한다.
2. 씬 원본의 `Space/Left click`, `Missile button`, `Special button` 안내를 최신 문구로 교체한다.
3. 육안 검증용 5락 카메라 진동 `×8` 상수를 최종 연출값으로 되돌린다.
4. 단발 미사일·Special·Legacy Bullet Hell 잔존 코드/에셋의 보존 여부를 결정한다.
