## 1. 상태 표기

| 상태 | 의미 |
| --- | --- |
| 구현됨 | 현재 BattleArena 기본 런타임 경로에서 사용됨 |
| 프로토타입/디버그 | 코드·UI가 있으나 숨겨진 입력, 개발 빌드 또는 디버그 조작에 의존 |
| 계획/미구현 | 기획 의도만 있거나 실제 전투 연결이 없음 |
| 레거시/비활성 | 소스나 에셋은 남아 있지만 현재 활성 경로에서 사용하지 않음 |
| 불일치 | 코드 기본값, 씬 값, 문서 또는 빌드 경로가 서로 달라 결정이 필요함 |

### 수치 단위 규칙

- `속도`는 별도 표기가 없으면 **Unity 월드 단위/초**다.
- `가속도`는 **Unity 월드 단위/초²**, `거리·폭·반경`은 **Unity 월드 단위**다.
- `피해`는 게임 내부 **피해량**, `HP/Hull/Armor`는 해당 체력 포인트다.
- `DPS`는 **초당 피해량**, `배율·스케일·비율`은 단위 없는 배수다.
- 시간은 `초`, 각도는 `도(°)`, 회전 속도는 `도/초(°/s)`, 화면 크기는 `px`로 쓴다.
- `viewport` 좌표는 화면 좌하단 `(0,0)`부터 우상단 `(1,1)`까지의 정규화 좌표다.

## 2. 게임 핵심 컨셉

Titan Destroyer는 화면 기준 2D 평면에서 헬기를 움직이며 단일 거대 타이탄을 상대하는 회피 슈팅 전투 게임이다.

현재 플레이의 핵심은 다음 세 가지다.

1. 입력 없이 반복되는 자동 기관총으로 지속 피해를 준다.
2. 우클릭 또는 모바일 `LOCK ON`을 유지해 최대 5개 부위를 순차 락온하고, 원하는 단계에서 놓아 미사일 일제사격을 실행한다.
3. 보스의 파편과 빔 경고를 보고 피하면서 Armor 수리 시간을 확보한다.

과거 문서의 단발 미사일, Special 버튼 필살기, 조준점 클릭, 확률 크리티컬은 현재 전투 기능이 아니다.

## 3. 게임 시작부터 BattleArena 진입

현재 빌드의 기본 흐름은 아래와 같다.

```text
Boot → IntroScene → MainMenu → StageStepSelectScene → BattleArena
```

| 단계 | 현재 동작 | 상태 |
| --- | --- | --- |
| Boot | `GameBootstrap`이 `IntroScene`을 로드 | 구현됨 |
| Intro | 입력 후 `MainMenu`로 이동 | 구현됨 |
| MainMenu | `Game Start`가 Single 모드로 `StageStepSelectScene`을 직접 로드 | 구현됨 |
| StageStepSelect | Tokyo/Seoul/Paris/Hollywood/Beijing과 난이도 4단계를 선택 | 구현됨 |
| BattleArena | 선택값을 HUD에 표시하고 동일한 전투 구성으로 시작 | 구현됨 |

구형 `StageSelectScene`은 Build Settings와 코드에 남아 있지만 현재 메인 메뉴 기본 흐름에서는 호출하지 않는다.

### 모드

| 모드 | 보스 HP | 진입 방식 | 상태 |
| --- | ---: | --- | --- |
| Single | 2,000 HP | 메인 메뉴 `Game Start` | 구현됨 |
| MultiPlaceholder | 2,800 HP | 메인 메뉴에서 `M` 키 | 프로토타입/디버그 |

MultiPlaceholder는 아군 플레이스홀더를 표시하지만 네트워크 협동, 역할 분담, 보상, 멀티 전용 난이도는 구현되지 않았다.

### 스테이지와 난이도

| 항목 | 선택 가능 값 | 실제 전투 영향 |
| --- | --- | --- |
| 지역 | Tokyo, Seoul, Paris, Hollywood, Beijing | HUD 디버그 표시에만 사용 |
| 난이도 | Easy, Normal, Expert, Nightmare | 전투 수치·패턴에 영향 없음 |

지역/난이도별 보스 HP, 피해량, 패턴, 플레이어 스탯, 전투 배경 변화는 미구현이다.

| 시점/조건 | 현재 동작 |

## 6. 플레이어 공격

현재 피해를 주는 공격은 자동 기관총과 락온 미사일 두 종류뿐이다.

### 6.1 자동 기관총 — 구현됨

| 항목 | 현재값 |
| --- | ---: |
| 1발 피해 | 3 피해/발 |
| 발사 간격 | 0.15초 |
| 발사 구간 | 2초 |
| 휴지 구간 | 2초 |
| 탄속 | 60 월드 단위/초 |
| 탄 수명 | 4초 |
| 이론 발사 구간 DPS | 20 피해/초 |
| 이론 4초 주기 평균 DPS | 10 피해/초 |

- 전투 시작 시 발사 구간부터 시작한다.
- 보스의 고정 `AimPoint`를 향한다.
- 확률 크리티컬과 부위별 피해 배율은 사용하지 않는다.
- 락온 충전·미사일 발사 중에도 기관총은 계속 동작한다.

### 6.2 락온 미사일 — 구현됨

| 성공 락 | 누적 충전 | 미사일 수 | 총 기본 피해량 | 1발 기본 피해량 |
| ---: | ---: | ---: | ---: | ---: |
| 1개 | 1.0초 | 5발 | 9 피해 | 1.8 피해/발 |
| 2개 | 2.5초 | 10발 | 20 피해 | 2.0 피해/발 |
| 3개 | 4.5초 | 15발 | 35 피해 | 약 2.333 피해/발 |
| 4개 | 7.0초 | 20발 | 60 피해 | 3.0 피해/발 |
| 5개 | 10.0초 | 30발 | 100 피해 | 약 3.333 피해/발 |

- 입력을 놓을 때 성공 락 수에 해당하는 프로필을 사용한다.
- 성공 락 0개면 발사와 재사용 대기 없이 취소된다.
- 정상 발사 승인 시 5초 재사용 대기가 시작된다.
- 충전 중 실제 피해를 받으면 충전·락·마커가 즉시 취소되며 같은 입력의 릴리즈는 발사되지 않는다.
- 한 웨이브당 최대 4발, 전체 발사 구간은 약 0.6초, 고정 풀은 40발이고 최대 요청은 30발이다.
- 일반 부위 배율은 1.0, 열린 약점은 2.0이다. 약점 개방 조건은 디버그에만 있어 기본 전투에서는 약점이 닫혀 있다.
- 실제 5락에서만 헬기 0.3초 반전, 장착 Sidewinder 2발의 1초 점화·분리, 화면 진동을 실행한다. 장착 Sidewinder는 피해 0의 시각 연출이며 30발/총 피해 100에 포함되지 않는다.
- 1~4락은 약 0.6초 발사 완료까지, 5락은 장착 Sidewinder 분리 시점인 약 1.3초까지 일제사격 무적이다.

## 7. 플레이어 생존

| 항목 | 현재값 |
| --- | ---: |
| Hull | 100 Hull 포인트 |
| Armor | 120 Armor 포인트 |
| Armor 수리 시작 | 마지막 유효 피격 2.5초 후 |
| Armor 수리 속도 | 8 Armor/초 |
| Armor 파손 해제 | 36 Armor 이상 |
| 파손 중 Hull 피해 | 원시 피해의 1.25배 |
| 일반 피격 무적 | 최소 1초 |
| 패배 조건 | Hull 0 |

정상 상태에서는 Armor가 먼저 피해를 받는다. Armor가 이번 공격으로 깨지면 남은 피해에 1.25배를 적용해 Hull에 전달한다. 파손 상태에서는 Armor가 수리 중이어도 36에 도달하기 전까지 모든 유효 피해가 Hull에 1.25배로 적용된다.

추적 잔류 빔은 일반 피격 무적을 사용하지 않고 0.2초 전용 틱을 사용한다. 일제사격 무적은 일반 피해와 연속 피해를 모두 막는다.

## 8. 보스 공통 규칙

| 항목 | 현재값 |
| --- | ---: |
| Single HP | 2,000 HP |
| MultiPlaceholder HP | 2,800 HP |
| 기본 투사체 피해 | 15 피해/발 |
| 기본 투사체 속도 | 24 월드 단위/초 |
| 투사체 전역 스케일 | 원본 크기의 2.5배 |
| 빔/위험영역 전역 스케일 | 원본 폭·길이의 2.5배 |
| 첫 공격 지연 | 4초 |
| 기본 공격 간격 | HP 100%에서 1.8초 → HP 0%에서 0.9초 |

공격 간격은 다음 공식으로 계산하며 각 패턴 종료 후 적용한다.

```text
기본 공격 간격 = Lerp(0.9, 1.8, 보스 현재 HP 비율)
실제 다음 패턴 대기 = 기본 공격 간격 × 패턴 쿨다운 배율
```

보스는 Armor와 피격 무적이 없으며 유효한 양수 피해를 HP에서 바로 차감한다.

## 9. 활성 보스 패턴

현재 `BattleArena` 씬에 직렬화된 활성 순서는 4종이다.

```text
Debris Fragment Scatter
→ Debris Salvo
→ Accelerating Sweep Beam
→ Tracking Residual Beam(HP 65% 이하에서만 선택)
→ 반복
```

HP 65% 초과에서는 Tracking Residual Beam을 건너뛰므로 앞의 3종만 반복한다.

### 9.1 Debris Fragment Scatter — 구현됨

**공격 모양:** 보스가 꼬리를 내리찍은 뒤 꼬리 충돌 지점에서 작은 돌·금속 파편 7~10개가 부채꼴 소나기처럼 연속으로 튀어나온다. 각 파편은 빠르게 회전하면서 짧은 노랑→주황→빨강 꼬리를 남긴다. 이 중 3~4개는 플레이어 근처의 좁은 한 덩어리로 몰리고, 나머지는 화면의 더 넓은 범위로 흩어진다. 하늘에서 떨어지는 공격이 아니라 보스의 꼬리 쪽 한 지점에서 플레이어 화면 평면을 향해 직선으로 퍼지는 산탄형 공격이다.

**회피 포인트:** 꼬리 동작과 가느다란 경고선을 본 뒤, 파편이 조밀하게 모이는 중심에서 먼저 벗어난다. 중심을 피한 뒤에도 바깥쪽에 흩어진 파편이 있으므로 짧게 한 번만 움직이기보다 빈 공간을 확인하면서 이동해야 한다.

| 항목 | 현재값 |
| --- | ---: |
| 파편 수 | 7~10개 |
| 발사 간격 | 0.025초 |
| 1개 피해 | 5.25 피해/개 |
| 이동 속도 | 6 월드 단위/초 |
| 최종 생성 스케일 | 원본의 1.125배 |
| 쿨다운 배율 | 기본 공격 간격의 0.9배 |
| 현재 준비 시간 | Tail 릴리즈 큐 1.6초 |
| 카메라 흔들림 | 릴리즈 시 0.1초, 카메라 로컬 위치 진폭 0.24 월드 단위 |

현재 카이주 애니메이션 경로는 `TailImpact`와 Tail 클립의 `48/30초` 릴리즈 큐를 사용한다. 씬의 `telegraphDuration=0.25`는 실제 대기 시간을 결정하지 않는다. `0.2초 스톰프 2회`는 AnimationDriver가 없을 때의 폴백이다.

### 9.2 Debris Salvo — 구현됨

**공격 모양:** 보스의 입 쪽 발사점에서 대형 투사체를 한 번에 퍼뜨리지 않고 2~4발 차례로 던진다. 첫 발 전에는 보스와 목표 지점을 잇는 얇은 주황색 직선 경고가 보인다. 각 투사체는 멀리 있을 때 작게 시작하고 접근할수록 크게 부풀어 보이며, 느린 초기 속도에서 계속 가속해 화면 앞으로 돌진한다. 패턴 이름과 역할은 “대형 파편”이지만 현재 실제 외형은 불규칙한 바위가 아니라 주황색 구체형 `BossProjectile`이므로, 화면에서는 큰 주황색 에너지탄이 한 발씩 연속으로 날아오는 모습에 가깝다.

**회피 포인트:** 첫 경고선이 가리킨 자리를 벗어난 뒤에도 멈추지 않는다. 후속 파편은 발사할 때마다 플레이어 주변의 새 지점을 다시 겨냥하므로, 한곳에 서거나 첫 발을 피한 직후 되돌아가면 다음 대형 파편에 맞기 쉽다.

| 항목 | 현재값 |
| --- | ---: |
| 발사 수 | HP 손실 1/3 미만 2발 / 1/3 이상 3발 / 2/3 이상 4발 |
| 첫 발 경고 | 0.3초 |
| 발사 간격 | 0.2초 |
| 1발 피해 | 23.25 피해/발 |
| 현재 보이는 외형 | 주황색 구체형 `BossProjectile` |
| 기본 계산 속도 | 12 월드 단위/초 |
| 실제 초기 속도 | 6 월드 단위/초, 목표 도달 1초 기준으로 가속 |
| 최종 생성 스케일 | 원본의 7.0배 |
| 접근 크기 변화 | 최종 생성 크기의 0.25배 → 1.19배 |
| 쿨다운 배율 | 기본 공격 간격의 1.05배 |

### 9.3 Accelerating Sweep Beam — 구현됨

**공격 모양:** 보스의 입에서 화면 한쪽 끝을 향한 길고 가는 경고 빔이 먼저 나타난다. 0.8초 뒤 굵은 붉은 빔으로 바뀌어 플레이어가 있던 화면 높이를 따라 반대쪽 끝까지 수평으로 쓸고 지나간다. 자동차 와이퍼나 탐조등이 회전하듯 입을 축으로 좌→우 또는 우→좌로 회전하며, 처음 20% 구간은 천천히 움직인 뒤 남은 80%를 매우 빠르게 휩쓴다. 빠른 구간에서는 빔도 조금 더 굵고 붉어진다.

**회피 포인트:** 빔 진행 방향과 현재 수평 라인을 확인하고 경고 중에 위나 아래로 충분히 벗어난다. 초반이 느려 보여도 후반 0.2초에 급가속하므로 빔을 따라 옆으로 달리거나 마지막 순간에 피하려 하면 불리하다.

| 항목 | 현재값 |
| --- | ---: |
| 방향 | 사용할 때마다 좌/우 무작위 |
| 경고 | 0.8초 |
| 느린 구간 | 전체 경로 첫 20%, 0.3초 |
| 빠른 구간 | 나머지 80%, 0.2초 |
| 총 횡단 | 0.5초 |
| 1회 피해 | 18 피해/피격 |
| 기본 폭 | 1.95 월드 단위, 빠른 구간 최대 1.18배 |
| 길이 | 70 월드 단위 |
| 쿨다운 배율 | 기본 공격 간격의 1.2배 |

씬의 92도 값은 화면 좌우 경로 계산에 실패했을 때만 쓰는 폴백이다. 정상 경로는 플레이어 깊이와 화면 높이의 viewport X `-0.08~1.08`을 잇는다.

### 9.4 Tracking Residual Beam — 구현됨

**공격 모양:** 보스의 입에 주황색 구형 에너지가 0.5초 동안 맥동한 뒤, 입에서 플레이어 쪽으로 길고 굵은 붉은 빔이 연결된다. 빔의 끝점이 플레이어 현재 위치를 제한된 속도로 따라가므로, 빔 전체가 보스 입을 축으로 계속 방향을 틀며 4초 동안 추적한다. 이름에 Residual이 들어가지만 현재 구현은 바닥에 잔류 장판이나 지나간 자리에 남는 빔을 만드는 형태가 아니라, 보스와 추적 지점을 계속 잇는 지속형 레이저에 가깝다.

**회피 포인트:** 충전 구체가 보이면 미리 이동을 시작하고, 발사 후에는 한 방향으로 계속 움직여 빔 끝점과 거리를 벌린다. 화면 가장자리에 몰리면 다음 이동 공간이 없어지므로 가능하면 중앙 쪽에 회피 여유를 남겨야 한다. 접촉을 유지하면 0.2초마다 연속 피해가 들어온다.

| 항목 | 현재값 |
| --- | ---: |
| 활성 조건 | 보스 HP 65% 이하 |
| 준비 | 0.5초 |
| 지속 | 4초 |
| 추적 속도 | 플레이어 기준 최대 속도의 0.4배, 현재 보통 4 월드 단위/초 |
| 피해 | 0.2초마다 3 피해/틱 |
| 이론 DPS | 15 피해/초 |
| 4초 최대 원시 피해 | 60 피해 |
| 폭 | 1.55 월드 단위 |
| 길이 | 70 월드 단위 |
| 쿨다운 배율 | 기본 공격 간격의 1.35배 |

직렬화된 피해 배율 `damageMultiplier=0.95배`, 경고 시간 `telegraphDuration=0.7초`, 회전 속도 `trackingTurnRate=28°/s`, 준비 추적 속도 배율 `0.5배`는 현재 실행 공식에서 사용하지 않는다.
