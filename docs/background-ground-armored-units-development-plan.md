# Background Ground Armored Units 개발계획서

## 1. 목적

BattleArena의 거대 몬스터 주변에 7~10대 규모의 지상 장갑차량을 배치해, 기존 배경 헬기와 함께 전장 전체가 움직이고 싸우는 것처럼 보이게 한다.

지상 부대는 다음 세 종류로 구성한다.

1. 탱크
2. 대형 개틀링건 탑재 차량
3. 박격포 차량

일부 차량은 2~3대 단위 편대 또는 종대를 이루고, 일부 차량은 독립적으로 이동한다. 차량은 몬스터 주변 경로를 순환하면서 이동 사격하거나, 자연스럽게 감속·정차해 사격한 뒤 다시 대열과 경로에 합류한다.

이 시스템은 기존 공중 배경 헬기와 같은 **순수 배경 전투 연출**이다. 지상 차량의 포탄·총탄·폭발은 보스 체력, 플레이어 Hull/Armor, 락온 타깃, 보스 패턴, 승패 조건에 영향을 주지 않는다.

## 2. 현재 상태

상태: **프로토타입 구현 / 기본 8대 배치 및 배치 Play Mode 검증 완료**

최적화된 차량 3종을 독립 Prefab으로 만들고 BattleArena에 기본 8대 편성을 연결했다. 모든 차량은 관리자 하나에서 StageVisualRoot 로컬 폐회로를 거리 기준으로 이동하며, 포탑·포신·총구 앵커를 사용해 이동/정차 사격을 연출한다. 공격은 고정 LineRenderer 풀만 사용하며 실제 피해 API를 호출하지 않는다.

| 항목 | 현재 상태 | 다음 조건 |
| --- | --- | --- |
| 공중 배경 헬기 | 구현됨 | 기존 동작과 전투 불변식 유지 |
| 지상 차량 3종 | 구현됨 | 800 / 779 / 820 tris, 공용 256/128 텍스처·Material |
| 지상 이동 경로 | 프로토타입 구현 | StageVisualRoot 로컬 Catmull-Rom 폐회로 3개, 거리 샘플링 |
| 편대·개별 이동 | 프로토타입 구현 | 기본 8대(3/3/2), 3대 종대 + 지원 2대 + 독립 3대 |
| 이동 사격·정차 사격 | 프로토타입 구현 | 탱크/개틀링 이동 사격, 세 차종 감속·정차·조준·사격·복귀, 간헐적 포구 화염 |
| 공중·지상 공격 조율 | 구현됨 / 통합 육안 검증 대기 | Primary 1개 + Ambient 2개 공용 예산 |
| 실제 피해·충돌 | 제외 | 배경 연출 전용으로 유지 |

이 문서의 수치 중 `초기안` 또는 `권장 범위`로 표시한 값은 에셋과 실제 Game View 확인 전의 튜닝 시작점이다. 구현 완료값으로 간주하지 않는다.

## 3. 목표 범위

### 3.1 필수 범위

- 지상 장갑차량 총 7~10대 표시.
- 탱크, 대형 개틀링건 탑재 차량, 박격포 차량 3종 혼합.
- 2~3대 단위 편대·종대와 독립 차량을 동시에 운용.
- StageVisualRoot와 함께 회전하는 지상 로컬 경로 사용.
- 몬스터 주변을 순환하되 화면 중심을 계속 가리지 않는 복수 경로 사용.
- 차량별 속도, 출발 위상, 정차 시간, 사격 간격, 반응 지연 차이.
- 선두 차량을 따르는 편대 이동과 차량 간 최소 간격 유지.
- 탱크의 이동 사격과 정차 사격.
- 대형 개틀링건 차량의 이동 버스트와 정차 집중 버스트.
- 박격포 차량의 감속·정차·발사·복귀 흐름.
- 공중 헬기와 큰 공격 연출이 과밀하게 겹치지 않도록 전역 연출 예산 공유.
- 모든 총탄·포탄·폭발 VFX의 고정 풀 사용.
- 전투 종료, Retry, Quit에서 유닛·VFX·이벤트 완전 정리.

### 3.2 제외 범위

- 지상 아군의 실제 보스 피해.
- 지상 아군 체력, 피격, 파괴 판정.
- 플레이어가 지상 부대를 선택하거나 명령하는 UI.
- NavMesh 기반 전술 AI, 엄폐, 장애물 회피 전투.
- 차량 간 물리 충돌과 Rigidbody 서스펜션.
- 보스 공격에 대한 실시간 회피 판단.
- 락온 후보 또는 약점 타깃 등록.
- 플레이어/보스 실제 Projectile 프리팹 재사용.
- 난이도별 지상 아군 화력 또는 생존 밸런스.
- 에셋 최적화 완료 전 모델 구조를 가정한 최종 프리팹 제작.

## 4. 기본 편성안

### 4.1 총원

| 프리셋 | 총 차량 | 용도 |
| --- | ---: | --- |
| 최소 | 7대 | 좁은 화면비·저사양 확인 |
| 기본 | 8대 | 기본 BattleArena 연출 |
| 최대 | 10대 | 성능·과밀도 상한 검증 |

기본 8대 편성의 초기안은 다음과 같다.

| 차종 | 기본 수 | 역할 |
| --- | ---: | --- |
| 탱크 | 3대 | 선두 전개, 이동/정차 포격, 편대 기준 제공 |
| 대형 개틀링건 탑재 차량 | 3대 | 이동 버스트, 정차 집중 사격, 화면상 연속 화력 |
| 박격포 차량 | 2대 | 후방 독립 이동, 정차 간접 사격, 큰 포물선 연출 |

정확한 차종별 수량은 실제 실루엣과 화면 크기를 보고 Inspector/Profile에서 조정한다. 특정 차종이 지나치게 크거나 시선을 많이 차지하면 총원 8대를 유지하면서 해당 차종 수만 줄인다.

### 4.2 그룹 구성 초기안

```text
GroundArmoredUnits
├─ ArmoredColumn_A       # 탱크 중심 3대 종대
├─ FireSupportPair_B     # 개틀링건 차량 + 박격포 차량 2대
└─ IndependentUnits      # 나머지 2~5대가 서로 다른 위상으로 독립 이동
```

- **ArmoredColumn_A:** 선두 탱크를 기준으로 2대가 경로 거리 오프셋을 유지한다.
- **FireSupportPair_B:** 완전히 밀착하지 않고 넓은 간격을 둔다. 박격포 차량이 정차하면 개틀링건 차량은 경로를 계속 진행하거나 별도 정차 슬롯을 사용한다.
- **IndependentUnits:** 같은 경로를 쓰더라도 시작 위상과 속도 seed를 다르게 해 한 덩어리처럼 보이지 않게 한다.
- 한 그룹 안에서 모든 차량이 같은 프레임에 가속·감속·사격하지 않는다. 리더 신호 뒤 0.15~0.6초의 역할별 지연을 적용한다.

### 4.3 편성 자연스러움 원칙

- 7~10대를 화면에 균등 간격으로 줄 세우지 않는다.
- 화면에 동시에 잘 보이는 차량은 기본 4~7대로 유지하고 나머지는 화면 가장자리·지형 뒤·경로 외곽을 순환하게 한다.
- 같은 차종끼리도 속도, 경로 오프셋, 정차 빈도, 포탑 회전 반응을 조금씩 다르게 한다.
- 박격포 차량 두 대가 동시에 같은 위치에서 같은 각도로 발사하지 않게 한다.
- 편대 전체의 정차 사격과 독립 차량의 이동 사격이 교차하도록 연출한다.

## 5. 좌표계와 씬 구조

### 5.1 좌표 소유권

공중 헬기는 카메라·보스 상대 좌표를 사용하지만, 지상 차량은 지면과 함께 움직여야 하므로 **StageVisualRoot 로컬 좌표**를 기준으로 한다.

```text
BattleArenaRoot
└─ AmbientAllyArmyRoot
   ├─ BackgroundCosmeticCombatBudget  # 공중·지상 Primary/Ambient 예산
   ├─ AirRoot                         # 기존 공중 부대
   ├─ CosmeticVfxRoot                 # 기존 공중 VFX 풀
   └─ GroundArmoredUnits
      ├─ GroundUnitsRoot              # 런타임 차량 8대
      └─ GroundCosmeticVfxRoot        # 지상 고정 VFX 풀

StageVisualRoot
└─ GroundBinding 또는 GroundRouteNetwork의 실제 부모/바인딩 기준
```

최종 부모 구조는 현재 BattleArena의 StageVisualRoot 회전 방식과 사용자가 작업 중인 씬 변경을 확인한 뒤 결정한다. 어떤 구조를 사용하더라도 경로 샘플과 차량 위치는 StageVisualRoot 로컬 공간에서 계산한다.

### 5.2 경로 구성

초기에는 NavMesh 대신 저작된 폐회로/왕복 웨이포인트 또는 베이크된 스플라인을 사용한다.

| 경로 | 목적 | 초기 구성 |
| --- | --- | --- |
| Route_Outer | 대형 순환, 독립 차량과 박격포 차량 | 넓은 곡률, 화면 가장자리 통과 |
| Route_Middle | 탱크·개틀링 편대 | 몬스터 주변 중거리 순환 |
| Route_Support | 정차 사격과 화면 밖 재진입 | StopBay·FiringZone 비중 높음 |

각 경로는 다음 데이터를 가진다.

- StageVisualRoot 로컬 위치.
- 진행 방향과 지면 Up 방향.
- 누적 거리 기반 샘플링 데이터.
- 경로 폭과 차선 오프셋.
- 속도 제한 구간.
- 이동 사격 허용 구간.
- 감속 시작점, 정차점, 재가속 종료점.
- 화면 중심 회피 또는 VFX 금지 구간.
- 화면 밖 스폰·숨김·재배치 가능 구간.

### 5.3 지면 정합

- 초기 런타임은 매 프레임 지면 Raycast를 사용하지 않는다.
- 경로 저작 또는 Editor 베이크 단계에서 위치와 지면 법선을 저장한다.
- 차량은 저장된 지면 법선에 맞춰 제한된 피치·롤만 적용한다.
- 급경사에서 차체가 과도하게 기울지 않도록 차종별 최대 피치·롤을 둔다.
- 지형 메시가 변경되면 경로를 다시 베이크하고 Scene View Gizmo로 이격·관통을 확인한다.
- StageVisualRoot가 회전해도 차량 로컬 접지점과 진행 방향이 함께 회전해야 한다.

## 6. 이동 시스템 설계

### 6.1 중앙 집중 갱신

차량마다 독립 `Update`를 붙이지 않는다. 지상 부대 관리자 하나가 모든 차량의 상태, 경로 진행률, 편대 목표, 포탑/포신, VFX 수명을 갱신한다.

```text
BackgroundAllyArmyController
└─ BackgroundGroundArmoredUnitsRuntime
   ├─ GroundGroupRuntime[]
   ├─ GroundUnitRuntime[]
   ├─ RouteReservationRuntime
   └─ GroundCosmeticAttackRuntime
```

- View 컴포넌트는 Transform과 Renderer, 무장 앵커만 캐시한다.
- 매 프레임 `Find*`, LINQ, 배열 생성, 문자열 조합을 사용하지 않는다.
- 모든 차량과 VFX는 전투 시작 또는 씬 구성 시 미리 생성한다.
- 정해진 seed를 사용해 Retry마다 재현 가능하게 만들 수 있도록 한다.

### 6.2 거리 기반 경로 이동

경로 진행을 웨이포인트 인덱스가 아니라 누적 거리로 관리한다.

```text
distance += currentSpeed × deltaTime
sample = route.EvaluateByDistance(distance + laneOffset)
```

- 선두 차량은 자기 경로 거리를 직접 진행한다.
- 편대원은 선두 Transform을 쫓지 않고 `leaderDistance - followDistance`를 샘플링한다.
- 이 방식으로 곡선에서 편대원이 안쪽을 가로지르는 현상을 막는다.
- 폐회로 끝에서는 누적 거리를 래핑한다.
- 왕복 경로에서는 끝점 전에 감속하고 진행 방향을 반전한다.

### 6.3 속도와 가감속

에셋 스케일 확인 전 초기 상대값은 다음과 같다.

| 차종 | 순항 속도 배율 | 가속 특성 | 감속 특성 |
| --- | ---: | --- | --- |
| 탱크 | 1.00 | 무겁고 완만함 | 정차 사격 전 충분히 감속 |
| 대형 개틀링건 차량 | 1.08 | 탱크보다 빠름 | 짧은 제동과 빠른 재가속 |
| 박격포 차량 | 0.88 | 가장 느림 | 정차점에 일찍 접근해 안정적으로 정지 |

실제 기본 속도는 차량 크기와 BattleArena 경로 길이를 확인한 뒤 정한다. 기본 한 바퀴 시간은 기존 헬기보다 길게 두고, 화면 안에서 차량이 미끄러지거나 장난감처럼 빠르게 보이지 않는 값을 우선한다.

공통 속도 상태:

```text
Cruise
  → EaseDown
  → Hold 또는 FireWhileRolling
  → EaseUp
  → Cruise
```

- 속도는 `MoveTowards` 또는 지수 감쇠로 보간한다.
- 정차 직전 급정지하지 않도록 감속 거리를 경로에 예약한다.
- 재출발 시 첫 프레임부터 순항 속도를 사용하지 않는다.
- 그룹 차량은 같은 목표 속도를 사용해도 ±3~6%의 장기 편차와 짧은 반응 지연을 가진다.

### 6.4 간격과 정차 예약

물리 충돌 대신 경로 예약 데이터로 차량 간 간격을 유지한다.

- 같은 차선의 앞 차량까지 남은 경로 거리를 계산한다.
- 안전 간격 이하이면 뒤 차량 목표 속도를 부드럽게 줄인다.
- StopBay는 동시에 1대 또는 지정된 편대만 점유한다.
- 박격포 차량이 정차점을 점유 중이면 뒤 차량은 다른 차선으로 보내지 않고 충분한 거리에서 서행하거나 해당 정차점을 건너뛴다.
- 편대 차량은 리더가 정차하더라도 일정 시간차로 멈춰 차량이 겹치지 않게 한다.
- 화면 밖에서만 순간적인 거리 재배치가 가능하며 화면 안에서는 텔레포트하지 않는다.

### 6.5 조향과 차체 자세

- 경로 접선 방향을 차량 +Z 전방으로 사용한다.
- 회전은 시간 기반 `Quaternion.Slerp` 또는 지수 감쇠로 보간한다.
- 차체는 지면 법선에 제한적으로 맞추되 포탑 조준과 분리한다.
- 차종별 최소 회전 반경보다 급한 경로 곡선은 저작 단계에서 금지한다.
- 선회 중 편대 간격을 넓히고 직선 구간에서 기본 간격으로 복귀시키는 선택적 보정을 둔다.

## 7. 전투 연출 디렉터

### 7.1 두 단계 연출 예산

7~10대가 모두 동시에 사격하면 배경 연출이 플레이어 공격과 보스 경고를 가리므로, 큰 공격과 작은 사격을 구분한다.

| 예산 | 동시 허용 | 예시 |
| --- | ---: | --- |
| Primary Cosmetic Attack | 전체 공중+지상에서 1개 | 박격포 일제사격, 탱크 편대 정차 포격, 헬기 공격 진입 |
| Ambient Fire | 지상에서 기본 2대 | 탱크 단발 이동 사격, 짧은 개틀링 이동 버스트 |

- 기존 헬기의 `Approach → AttackRun → BreakAway → Rejoin`은 Primary 슬롯을 사용한다.
- 박격포의 큰 포물선과 탱크 편대 정차 포격도 같은 Primary 슬롯을 사용한다.
- 저채도·저밝기의 짧은 이동 사격만 Ambient 예산을 사용할 수 있다.
- 보스의 큰 텔레그래프나 플레이어 5락 풀살보 중에는 Primary 시작을 지연할 수 있다.
- 이미 시작된 연출을 갑자기 끊기보다 새 연출 예약만 늦춘다.

### 7.2 자연스러운 선택 규칙

공격 대상 차량을 완전 무작위로만 고르지 않고 다음 조건을 적용한다.

- 직전 공격 차량과 같은 차량은 연속 선택하지 않는다.
- 같은 차종이 2회 연속 Primary를 사용하면 다음 후보 가중치를 낮춘다.
- 화면 중앙에 이미 VFX가 많으면 박격포·대형 폭발 선택을 지연한다.
- StopBay가 비어 있고 경로상 감속 거리가 충분한 차량만 정차 공격 후보가 된다.
- 편대 전체가 급커브에 있으면 편대 포격을 시작하지 않는다.
- 화면 밖 차량은 발사 후보가 아니라 재배치·대열 복구 후보로 사용한다.
- 각 차량은 전투 시작 시 정한 seed로 미세한 선호 행동을 가진다.

## 8. 차종별 행동 설계

### 8.1 탱크

역할: 가장 안정적으로 보이는 전방 장갑차량. 편대 리더와 독립 차량 양쪽에 사용할 수 있다.

상태 흐름:

```text
Cruise
  ├─ AimWhileMoving → FireOnMove → RecoverAim → Cruise
  └─ ReserveStopBay → Brake → HaltAim → HaltFire
       → RecoilHold → Accelerate → Rejoin → Cruise
```

이동 사격:

- 포탑이 몬스터 방향으로 먼저 회전한다.
- 포탑 오차가 허용 범위 안이고 경로가 완만할 때만 발사한다.
- 1회 1발을 기본으로 하며 짧은 포구 섬광, 포탄 궤적, 원거리 소형 폭발을 사용한다.
- 단발 Ambient Fire가 끝나는 프레임에도 포구 섬광을 즉시 취소하지 않고, 차종별 0.075~0.19초 수명을 끝까지 재생한다.
- 차체는 계속 진행하고 포탑만 제한 각도로 몬스터를 추적한다.
- 포탑이 분리되지 않은 에셋은 이동 사격 빈도를 낮추고 차량 전방에 가까운 구간에서만 발사한다.

정차 사격:

- 정차점 예약 후 1.0~2.0초에 걸쳐 감속한다.
- 완전히 멈춘 뒤 0.4~0.9초 조준 대기를 둔다.
- 단발 또는 간격을 둔 2발을 발사한다.
- 발사 시 차체가 아닌 포신/포탑에만 작은 반동을 준다.
- 0.5~1.2초 회복 후 부드럽게 재가속한다.

### 8.2 대형 개틀링건 탑재 차량

역할: 이동 중 지속적인 총구 화염과 짧은 트레이서로 전장의 활기를 만든다.

상태 흐름:

```text
Cruise
  ├─ TrackTarget → RollingBurst → Cooldown → Cruise
  └─ ReserveStopBay → Brake → Brace → FocusedBurst
       → Cooldown → Accelerate → Cruise
```

이동 버스트:

- 0.35~0.8초의 짧은 버스트를 사용한다.
- 총구 화염은 빠르게 점멸하지만 모든 점멸마다 트레이서를 만들지 않는다.
- 트레이서는 버스트당 1~3개만 사용해 화면 과밀과 풀 고갈을 막는다.
- 이동 중 조준 오차와 산포를 정차 사격보다 크게 둔다.

정차 집중 버스트:

- 감속 후 짧은 Brace 동작을 거친다.
- 0.8~1.8초 버스트를 사용하되 플레이어 기관총보다 채도·밝기·굵기를 낮춘다.
- 총열 회전 Transform이 있으면 발사 전 가속, 발사 후 감속을 표현한다.
- 총열이 분리되지 않은 에셋은 총구 화염과 미세한 무장 진동만 사용한다.
- 집중 버스트 뒤에는 긴 쿨타임을 줘 계속 화면을 점유하지 않게 한다.

### 8.3 박격포 차량

역할: 움직임과 정차의 대비가 가장 큰 지원 차량. 큰 포물선으로 배경 화력의 종류를 보여준다.

상태 흐름:

```text
Cruise
  → SelectFiringBay
  → Brake
  → Deploy/Aim
  → Fire
  → Recoil/Smoke
  → Recover
  → Accelerate
  → Rejoin
  → Cruise
```

행동 규칙:

- 박격포는 기본적으로 이동 사격하지 않는다.
- 지정된 FiringBay에서만 정차·조준·발사한다.
- 정차 뒤 0.8~1.6초의 준비 시간을 둬 즉시 발사하는 느낌을 피한다.
- 한 번에 1~3발을 0.35~0.8초 간격으로 발사한다.
- 발사체는 포물선 LineRenderer/Trail 또는 풀링된 시각 포탄을 사용한다.
- 착탄점은 보스 중심을 직접 맞히지 않고 주변 지면 오프셋을 사용한다.
- 폭발은 보스 실제 피격 VFX보다 작고 어둡게 표시하며 피해 숫자와 피격 틴트를 만들지 않는다.
- 발사 후 연기와 무장 복귀를 0.8~1.5초 보여준 뒤 재출발한다.
- 두 박격포 차량의 발사 시점, 고각, 착탄 위치를 서로 다르게 한다.

## 9. 에셋 인수 조건

에셋 최적화가 완료되면 구현 전에 각 차종을 아래 기준으로 검수한다.

### 9.1 공통 구조

권장 프리팹 구조:

```text
BackgroundGroundVehicle_*
├─ VisualRoot
│  ├─ Hull
│  ├─ TurretYaw 또는 WeaponYaw       # 있으면 사용
│  │  └─ GunPitch 또는 WeaponPitch   # 있으면 사용
│  │     └─ Muzzle                    # 필수 권장
│  └─ WheelsOrTracks                  # 선택
├─ GroundPivot                        # 바닥 중앙 기준
└─ VfxAnchors                         # 선택
```

필수 또는 권장 조건:

- Unity 전방축 +Z, Up +Y.
- 루트 스케일 `(1,1,1)` 권장.
- GroundPivot이 차량 바닥 중앙에 위치.
- Renderer Bounds에 불필요한 원거리 오브젝트가 포함되지 않음.
- 차체, 포탑/무장 회전축, 포신 Pitch 축, 총구 위치가 명확함.
- 무장 분리가 불가능하면 해당 사실을 기록하고 대체 연출을 사용.
- Collider와 Rigidbody는 포함하지 않거나 배경 프리팹 생성 시 제거.
- 같은 차종 인스턴스가 shared Mesh/Material을 사용.
- 텍스처와 Material 수가 확정되고 GPU Instancing 가능 여부를 확인.
- 원본 대비 최적화 외형 비교 이미지 또는 기준 파일 보존.

### 9.2 차종별 추가 앵커

| 차종 | 확인할 Transform/정보 |
| --- | --- |
| 탱크 | `TurretYaw`, `GunPitch`, `Muzzle`, 반동 가능한 포신 여부 |
| 대형 개틀링건 차량 | `WeaponYaw`, `WeaponPitch`, `Muzzle` 1개 이상, 회전 가능한 총열 여부 |
| 박격포 차량 | `MortarYaw` 선택, `MortarPitch`, `Muzzle`, 포신/발사대 복귀 자세 |

### 9.3 에셋 전달 시 기록할 값

에셋 파일이 준비되면 각 차종별로 다음 값을 문서에 추가한다.

- 최종 FBX/Prefab 경로.
- 삼각형 수와 Mesh 수.
- Material 수와 텍스처 해상도.
- 실제 월드 크기와 Bounds.
- 전방축과 피벗 검증 결과.
- 포탑/포신/총열 분리 여부.
- Muzzle 로컬 위치와 방향.
- LOD 또는 그림자 정책.
- 최적화 전후 비교 결과.
- 모바일 목표 기기에서 허용 가능한 동시 표시 수.

## 10. VFX·오디오 정책

### 10.1 VFX 풀 초기안

| VFX | 초기 풀 크기 | 사용처 |
| --- | ---: | --- |
| 짧은 기관총 트레이서 | 16 | 개틀링 이동/정차 버스트 |
| 탱크 포탄 궤적 | 6 | 탱크 이동/정차 포격 |
| 박격포 시각 포탄 | 6 | 박격포 2대의 시차 발사 |
| 총구 섬광 | 10 | 차량별 무장 공용 |
| 원거리 착탄 폭발 | 8 | 탱크·박격포 공용 |
| 지면 먼지/재출발 먼지 | 8 | 감속·정차·재가속 |
| 발사 연기 | 6 | 탱크·박격포 포구 |

- 풀 고갈 시 새로 Instantiate하지 않고 해당 연출을 생략한다.
- VFX 풀은 실제 동시성 측정 후 줄이거나 늘린다.
- 트레이서와 포탄은 Collider, Rigidbody, Damage 데이터를 가지지 않는다.
- 월드 파티클은 StageVisualRoot 회전과 수명 동안의 기준 공간을 명확히 정한다.
- 화면 중심과 플레이어 헬기 주변에서는 불투명도와 크기를 낮춘다.

### 10.2 오디오

초기 구현은 시각 연출 검증을 우선하고 전용 오디오는 선택 사항으로 둔다.

오디오를 추가할 경우:

- `GlobalSoundSettings`와 AudioListener 전역 상태를 따른다.
- 3D Spatial Blend와 짧은 최대 거리를 사용한다.
- 플레이어 기관총, 락온, 보스 경고보다 낮은 우선순위를 사용한다.
- 7~10대가 각자 AudioSource를 계속 재생하지 않도록 공용 풀 또는 제한된 소스를 사용한다.
- 이동 버스트마다 소리를 내지 않고 전역 사운드 쿨타임을 둔다.

## 11. 성능 예산

에셋 최적화가 끝나기 전까지 삼각형 총량은 확정하지 않는다. 전달된 실제 값을 기준으로 최대 10대 구성을 다시 계산한다.

| 항목 | 목표 |
| --- | --- |
| 활성 차량 | 기본 8대, 최대 10대 |
| 런타임 관리자 | 지상 부대 전체 1개 Update/LateUpdate 경로 |
| 차량 Collider/Rigidbody | 0개 |
| 프레임당 GC Alloc | 0 B 목표 |
| 런타임 Instantiate | 전투 시작 후 0회 목표 |
| Material | 차종별 shared Material 우선, 총 개수 최소화 |
| 그림자 | Off로 시작, 접지감 필요 시 blob shadow 비교 |
| VFX 동시성 | Primary 1개 + Ambient 기본 2대 범위 |
| 화면상 차량 | 과밀 방지를 위해 기본 4~7대가 명확히 보이도록 구성 |

프로파일링은 공중 헬기 4대와 지상 차량 최대 10대가 동시에 활성화된 상태에서 수행한다.


최종 파일명은 전달되는 에셋 이름을 확인한 뒤 확정하며 임의로 기존 파일을 이름 변경하지 않는다.

## 14. 검증 계획

### 14.1 EditMode 테스트

- 경로 누적 거리와 폐회로 래핑.
- 거리 기반 위치·접선·지면 법선 샘플링.
- 경로 끝 왕복 반전.
- 편대 리더/팔로워 거리 오프셋.
- 곡선에서 편대원이 경로를 가로지르지 않는지 확인.
- 앞차 안전 간격에 따른 목표 속도 감소.
- StopBay 단일 점유와 해제.
- 감속·정차·재가속 상태 경계.
- 차종별 상태 머신 전이.
- 공중·지상 Primary 슬롯 동시성 1.
- 지상 Ambient Fire 동시성 상한.
- 같은 차량·같은 차종 연속 선택 억제.
- 풀 고갈 시 생성 대신 생략.
- 고정 seed의 재현성과 서로 다른 seed의 변이.

### 14.2 Play Mode 또는 전용 런타임 진단

- 기본 8대와 최대 10대 생성.
- 차종별 수량과 shared Mesh/Material 확인.
- Collider/Rigidbody 0개 확인.
- StageVisualRoot 회전 중 위치·접지 유지.
- 편대/개별 차량의 실제 화면 분포.
- 탱크 이동 사격과 정차 사격 전체 흐름.
- 개틀링 이동/정차 버스트와 트레이서 예산.
- 박격포 정차·발사·회복·재출발.
- 공중 헬기 공격과 지상 Primary 공격 비중첩.
- 전투 전후 보스 HP, 플레이어 Hull/Armor, 락온 후보 수 불변.
- 보스 사망·플레이어 사망 시 새 공격 차단.
- Retry 후 중복 차량·VFX·이벤트 없음.
- 10분 동안 오브젝트 수와 메모리 사용이 지속 증가하지 않음.

### 14.3 시각 합격 기준

- 7~10대가 모두 같은 속도와 간격으로 움직이지 않는다.
- 편대와 독립 차량이 한눈에 구분되지만 서로 다른 시스템처럼 분리돼 보이지 않는다.
- 이동 사격, 감속, 정차, 발사, 재출발 사이에 순간이동과 급격한 속도 변화가 없다.
- 차량이 지면에서 뜨거나 지형을 관통하지 않는다.
- 포탑·포신이 가능 범위를 넘어 차체를 뚫지 않는다.
- 박격포 포물선과 폭발이 보스 약점·빔 경고·락온 마커를 지속적으로 가리지 않는다.
- 배경 공격이 플레이어 공격보다 밝거나 굵게 보이지 않는다.
- 공중 헬기와 지상 차량이 동시에 보여도 주요 전투 가독성이 유지된다.
- 화면 밖 재배치와 경로 반복 지점이 눈에 띄지 않는다.

### 14.4 전투 불변식

- 지상 사격 전후 보스 HP 변화 0.
- 플레이어 Hull/Armor 변화 0.
- 락온 후보와 성공 락 변화 0.
- 최근 공격 타깃과 보스 피격 틴트 변화 0.
- 보스 공격 패턴 순서·간격·피해 변화 0.
- 피해 숫자 생성 0.
- 승패 조건 변화 0.

## 16. 중단·롤백 기준

아래 조건에서는 다음 단계로 진행하지 않고 해당 기능을 비활성화한다.

- 지상 연출이 보스 또는 플레이어 전투 수치를 변경함.
- 차량이 PlayerVisual 오버레이 레이어에 포함됨.
- 최대 10대에서 지속적인 GC Alloc 또는 런타임 Instantiate가 발생함.
- StageVisualRoot 회전 중 접지 오차를 안정적으로 해결하지 못함.
- 편대·정차 예약 오류로 화면 안에서 차량 겹침이나 텔레포트가 반복됨.
- 배경 포격이 보스 텔레그래프와 락온 가독성을 지속적으로 해침.
- Retry 후 차량, VFX, 이벤트가 중복됨.

롤백 단위:

- `enableGroundArmoredUnits = false`: 지상 부대 전체 비활성.
- `enableGroundCosmeticAttacks = false`: 이동만 유지하고 사격 비활성.
- 차종별 `enableTank`, `enableGatlingCarrier`, `enableMortarCarrier` 비활성.
- `enableFormationMovement = false`: 모든 차량을 독립 경로 이동으로 폴백.
- GroundArmoredUnitRoot 제거 시 기존 공중 헬기와 전투가 그대로 유지돼야 함.

## 17. 에셋 완료 후 결정할 항목

다음 값은 최적화 에셋이 준비된 뒤 실제 화면과 Prefab 구조를 보고 확정한다.

- 세 차종의 최종 Prefab 경로와 이름.
- 차종별 최종 수량과 기본 7/8/10대 프리셋.
- 실제 삼각형·Material·텍스처 예산.
- 포탑, 포신, 개틀링 총열, 박격포 발사대의 분리 여부.
- Muzzle 앵커의 수와 정확한 방향.
- 차량 크기에 맞는 경로 폭, 안전 간격, StopBay 길이.
- 실제 순항 속도와 가감속 시간.
- 탱크 이동 사격과 정차 사격 비율.
- 개틀링 버스트 길이와 트레이서 빈도.
- 박격포 발사 수, 포물선 높이, 착탄 반경.
- 화면에 동시에 명확히 보일 차량 수.
- 지면 경사에 허용할 최대 피치·롤.
- 그림자 또는 blob shadow 필요 여부.
- 배경 차량 전용 3D 오디오 필요 여부.
- 모바일 목표 기기의 최종 렌더·CPU 예산.

에셋 전달 전에는 이 항목을 임의로 구현 완료값으로 고정하지 않는다.

## 18. 에셋 전달 후 첫 작업 체크리스트

사용자가 에셋 파일 준비 완료를 알리면 다음 순서로 작업을 시작한다.

1. 사용자 작업 트리와 새 에셋 경로를 확인한다.
2. 세 차종의 Importer, Mesh, Material, 텍스처, Bounds를 기록한다.
3. 각 Prefab의 +Z 전방, +Y Up, GroundPivot을 확인한다.
4. 포탑·포신·총열·박격포 발사대·Muzzle 앵커를 확인한다.
5. BattleArena에 한 대씩 임시 배치해 화면 크기와 지면 접지를 비교한다.
6. 7/8/10대 예상 삼각형·Material·Renderer 비용을 계산한다.
7. 본 문서의 미정 수치와 에셋 표를 실제 값으로 갱신한다.
8. Phase 1 경로 네트워크부터 단계별로 구현하고 각 Phase 완료 조건을 검증한다.

에셋 검수 전에는 BattleArena 씬, 기존 공중 헬기, 전투 수치를 변경하지 않는다.
